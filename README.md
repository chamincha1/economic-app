# MARKET PULSE

**국내 주식시장 종합 시세·기술적 지표·금융 뉴스·AI 예측·백테스트 교육용 웹앱**  
**Korean Stock Market Intelligence & Forecasting Platform**

> **프로젝트 핵심 질문:** “주가가 얼마나 변했는가?”를 넘어, **“어떤 데이터가 함께 변했는가, 관련 뉴스는 무엇을 말하는가, 다음 거래일의 움직임은 얼마나 불확실한가, 그리고 그 예측을 검증할 수 있는가?”**

- **프로젝트 유형:** 고등학교 Python 수행평가 기반의 확장형 데이터 분석·AI 소프트웨어 프로젝트
- **주요 기술(현재):** Python, Streamlit, Pandas, NumPy, Plotly, FinanceDataReader
- **현재 추가된 기술:** scikit-learn, requests, NAVER 뉴스 검색 API(키 필요), OpenDART(키 필요), 시간순 ML 검증
- **분석 시장:** 대한민국 KOSPI·KOSDAQ을 우선 대상으로 함
- **문서 기준일:** 2026-11-11 (KST)
- **문서 성격:** 이번 개정판의 **실제 구현·테스트 범위**와 추가적인 **최종 확장 목표**를 구분한 실행 안내 및 개발 명세

**중요:** 본 개정판에는 실제로 **뉴스 검색 API 연동 코드·키워드 감성 분류·다음 거래일 로지스틱 회귀 확률 추정·시간순 백테스트**를 새로 구현했습니다. 온라인 API의 실제 응답 및 Windows 브라우저 구동은 아직 독립 검증이 필요합니다. **실시간 체결가·정교한 금융 언어 모델·5일 후 가격 예측·기업 재무제표 자동 집계**는 아직 없습니다. 모든 예측은 교육·연구용이며 투자 조언이 아닙니다.

## 1. 프로젝트 목적과 해결하려는 문제

### 1.1 문제 인식

일반적인 증권 사이트는 주가, 거래량, 차트, 뉴스, 공시 등을 각각 제공한다. 하지만 사용자는 여러 화면의 정보를 직접 찾아 연결해야 하며, 가격의 일시적 급변과 지속적인 추세, 뉴스의 실제 게시 시점, 예측의 신뢰성을 구분하기 어렵다.

특히 주가가 상승했다는 사실만으로 **상승의 원인**, **앞으로의 상승 여부**, **뉴스가 예측에 기여하는 정도**를 알 수 없다. 가격·거래량·뉴스·시장지수 등 서로 다른 데이터를 동일한 시간 기준으로 분석하고, 예측 성능을 과거 자료로 검증하는 과정이 필요하다.

### 1.2 해결 목표

MARKET PULSE는 다음 과정을 하나의 로컬 웹앱에서 수행하도록 설계한다.

**종목 검색 → 실제 시세 확인 → 가격·거래량·기술적 지표 분석 → 이례적 변화 탐지 → 뉴스·공시 확인 → AI 확률 예측 → 근거 제시 → 과거 예측 검증**

최종 결과는 ‘매수/매도’ 결론이 아니라, **데이터가 뒷받침하는 분석과 불확실성이 드러나는 예측**이어야 한다.

### 1.3 핵심 차별점

- **과거 설명과 미래 예측을 분리:** 급변 *탐지*와 향후 급변 *예측*은 서로 다른 기능이다.
- **숫자와 텍스트의 결합:** OHLCV·시장지표와 뉴스·공시를 같은 기준시각으로 연결한다.
- **근거 중심 AI:** 각 예측에 사용된 데이터 시점, 모델 버전, 주요 변수와 기사 링크를 보여준다.
- **반증 가능성:** 예측 결과를 보관하고 실제 결과로 검증하며 기준 모델과 비교한다.
- **오프라인 시연:** 네트워크가 없어도 교육용 가상 데이터로 기존 분석 기능을 시연한다.

## 2. 구현 현황: 개정판 코드와 추가 목표

### 2.1 코드 개정의 실제 범위 (2026-11-11)

업로드된 원래 `app.py`, `stock_core.py`, 기존 테스트 11개를 기반으로 새 모듈을 만들고 전체 파일을 하나의 폴더로 재구성했다. **확인된 기능은 정적 코드 검사·오프라인 데이터 시연·단위 테스트 결과**로 구분한다. 외부 API의 실접속과 실제 브라우저 화면 검사는 별도 검증이다.

| 항목 | 이번 개정판 상태 | 실제 동작·한계 |
|---|---|---|
| 기존 급변 탐지 분석 | **구현 및 테스트** | 종가 수익률, 과거 N일 Z점수, 거래량 배율, MDD, 공통 거래일 비교 유지 |
| 주가 데이터 다운로드 | **구현, 온라인 실접속 미검증** | `market_data.py`: NAVER→KRX 공급자 시도, 6자리 코드와 과거 일별 자료 |
| 출처·캐시 메타데이터 | **구현 및 모의 테스트** | `data_cache/<코드>.csv`, `<코드>.meta.json`, `fresh/cached` 구분 |
| 실데이터 기본 화면 | **구현 코드** | 사이드바 기본은 실데이터, 접속 오류 시 가상자료로 자동 전환하지 않음 |
| 오프라인 가상 데이터 | **구현 및 테스트** | 가상기업 A~D 가격, 가상뉴스 352개(실제 기사가 아님) |

| 종목코드 직접 입력 | **구현 코드** | 6자리 코드 입력; 이름 목록은 KRX에서 사용자가 직접 검색 실행 |

| 캔들·거래량 그래프 | **구현 코드** | OHLC가 있으면 캔들, 없으면 종가선, 거래량·RSI·이동평균 표시 |
| 기술적 지표 | **구현 및 테스트** | SMA·EMA·RSI(14)·MACD·볼린저밴드·ATR(OHLC 있을 때)·거래량 배율 |
| 뉴스 검색 API | **구현 및 모의 테스트** | NAVER 공식 뉴스 검색 API, API 키 필요, 제목·요약·링크 중심 |
| 뉴스 감성 분류 | **구현 및 테스트** | **키워드 규칙형 휴리스틱**, 금융 특화 학습 모델이 아님 |
| 공시 검색 API | **구현 및 모의 테스트** | OpenDART corp_code 매핑 및 공시 목록 조회, API 키 필요 |
| 다음 거래일 AI 예측 | **구현 및 오프라인 테스트** | 로지스틱 회귀, 1일 후 종가 상승 여부, 미보정 추정 확률 |

| Colab 실습 | **노트북 개정 및 정적 검사** | 별도 노트북에서 가상 가격·뉴스·ML 실습. Colab 실제 세션은 미검증 |
| 자동 테스트 | **33개 통과** | 기존 11개 + 새 모듈 22개. 실제 외부 API/브라우저 연동은 제외 |
| 실시간 체결가·호가 | **미구현** | 별도 라이선스와 인증이 있는 실시간 API 필요 |
| 실데이터 뉴스 기반 모델 실효성 | **미검증** | 실시간 수집 기록이 장기간 쌓이고 별도 시험기간 평가가 필요 |

### 2.2 중요한 구현 원칙

1. **실제 시세가 없으면 오류:** 다운로드 실패 + 사용 가능한 이전 캐시가 없다면 실제 가격을 만들지 않는다.
2. **캐시를 최신이라고 부르지 않음:** 메타데이터의 수집 시각과 마지막 거래일을 표시한다.
3. **현재 데이터 = 장 마감 일별 데이터:** 실시간 체결가, 매수·매도 주문량 및 정확한 거래대금이 아니다.
4. **뉴스 원문 재배포 금지:** 검색 API가 제공하는 메타데이터 중심으로 취급한다.
5. **뉴스 시점 보수적 처리:** 기사 공개와 첫 확인 시각 중 늦은 쪽이 예측 cutoff보다 이전이어야 과거 피처로 계산한다.
6. **감성 분류 수준의 명시:** 키워드 휴리스틱일 뿐 문맥을 완전히 이해하는 금융 AI가 아니다.
7. **예측의 검증 결과 동반:** Brier·정확도·기준 모델 성적과 시기를 함께 공개한다.
8. **자체 평가에 성공했다고 실전 수익성을 주장하지 않음:** 데이터 결함, 과적합 및 시장 환경 변화를 고려한다.

### 2.3 현재 검증이 불가능했던 범위

이번 제작 환경에는 Streamlit과 FinanceDataReader의 런타임 라이브러리가 설치되어 있지 않아 **실제 브라우저 구동** 및 **NAVER·KRX·OpenDART·NAVER 뉴스 API의 원격 응답**을 검증하지 못했다. 대신 가격 수집 실패·캐시·뉴스 API 응답·DART ZIP 파싱을 모의 객체로 테스트하고, Python 모듈을 컴파일했다. Windows 및 실제 서비스 인증키를 이용한 검증은 사용자 PC에서 추가로 수행해야 한다.

## 3. 최종 제품의 핵심 사용자 경험

### 3.1 주식 초보 사용자

1. 메인 화면에서 KOSPI·KOSDAQ의 최근 상태와 종목을 검색한다.
2. 기업명 또는 6자리 종목코드로 상세 화면을 연다.
3. 가격, 등락률, 거래량, 시가·고가·저가·종가와 최근 차트를 확인한다.
4. 이동평균·RSI·MACD·변동성 및 주요 이례적 거래일을 살펴본다.
5. 기업 관련 기사·공시의 제목, 출처, 공개 시각, 분석 요약을 확인한다.
6. AI 예측에서는 **기준시점과 목표시점이 표시된 확률 추정**을 확인한다.
7. 바로 아래의 **모델 검증 성적표**로 해당 예측을 어느 수준까지 신뢰할 수 있는지 판단한다.

### 3.2 데이터 분석 사용자

1. 실제 가격 데이터를 수집하거나 자체 CSV를 업로드한다.
2. 분석 기간·기준 창 크기·Z점수·거래량 배율을 변경한다.
3. 기업 간 가격 변화와 이례적 움직임을 비교한다.
4. 뉴스 변수 사용 여부를 바꿔 모델 성능을 실험한다.
5. 입력 데이터, 피처(특성), 예측값, 평가 결과를 CSV 등으로 내보낸다.

### 3.3 인터넷이 없는 수행평가 현장

**가상 데이터 모드로 통계 분석·탐지를 시연**한다. 예측 기능까지 오프라인으로 시연하려면 모델 파일과 필요한 피처를 사전에 준비하고, *가상 데이터에 대한 시연 예측*임을 명시해야 한다. 실제 주가나 실제 뉴스인 것처럼 표현하지 않는다.

## 5. 금융 데이터 수집·검증·저장

### 5.1 데이터 종류와 출처 후보

| 종류 | 후보 출처 | 활용 목적 | 주의사항 |
|---|---|---|---|
| 일별 주가·OHLCV | **FinanceDataReader** | 현재 버전의 주가 수집 | 외부 웹 데이터 제공처에 의존; 시세·조정 방식 확인 |
| 거래소 일별 시장 통계 | **KRX OPEN API** | 종목·지수 일별 정보 확장 | 서비스 승인·이용 조건·제공 항목 확인 필요 |
| 실시간/현재가 조회 | **한국투자증권 KIS Developers API** 등 | 향후 시세·체결 조회 | 인증·호출 제한·사용 권한 및 실시간 조건 확인 필요 |
| 기업 공시·재무 | **금융감독원 OpenDART** | 기업 실적·공시 데이터 | `stock_code`와 DART `corp_code`는 다름; 별도 매핑 필요 |
| 뉴스 검색 결과 | **NAVER 뉴스 검색 API** 등 | 제목·요약·원문 링크·게시시각 | 기사 원문 수집·저장·AI 학습 허용 여부 별도 확인 |
| 지수·거시경제 | 거래소·한국은행 등 적법한 데이터 서비스 | 시장·환율·금리 변수 | 수집 가능 시간과 관측일·공표시각 구분 |

> **연동 순서 권장:** FinanceDataReader 일별 가격 안정화 → KRX/지수·OpenDART → 뉴스 검색 API → 예측 모델 → 필요할 때만 실시간 시세 API.

### 5.2 가격 데이터 필드 정의

| 필드 | 의미 | 단위/검증 기준 |
|---|---|---|
| `Date` | 거래일 | `YYYY-MM-DD`; 날짜 중복 없음 |
| `Open` | 시가 | 원/주; 선택적, 양수 |
| `High` | 고가 | 원/주; 선택적, 해당 거래일 가격 관계 검사 |
| `Low` | 저가 | 원/주; 선택적, 해당 거래일 가격 관계 검사 |
| `Close` | 종가 | 원/주; **필수, 양수** |
| `Volume` | 거래량 | 주; **필수, 0 이상** |
| `source` | 데이터 제공처 | 제공처 이름/경로 |
| `retrieved_at` | 수집 시각 | 타임존 포함(UTC 저장·KST 표시 권장) |
| `last_trade_date` | 최종 포함 거래일 | 거래소 휴일 반영 |
| `adjusted_price` | 가격 조정 여부 | `true`/`false`/`unknown`; 제공처 확인 |
| `data_status` | 데이터 상태 | `fresh`, `cached`, `demo`, `uploaded`, `error` 등 |

`Volume`은 **체결된 주식 수량**이다. **매도 주문 수량·매수 주문 수량·기업 매출액과 같지 않다.** 매수/매도별 호가, 체결강도, 체결 주체를 보여주려면 전용 데이터가 추가로 필요하다.

또한 **거래대금**은 별도의 시장 데이터 필드가 존재하는 경우 그 값을 쓴다. 종가×거래량은 일반적으로 실제 하루 거래대금과 일치하지 않으므로, 계산하여 표시한다면 반드시 **추정치**라고 표기한다.

### 5.3 데이터 수집 흐름(개정판 구현)

```text
사용자 종목 선택
    ↓
종목코드·거래소 확인
    ↓
로컬 캐시 존재 및 수집 시각 확인
    ↓
기간별 온라인 수집 시도
    ├─ 성공 → 데이터 정합성 검증 → CSV 저장 + 메타데이터 저장
    └─ 실패 → 검증된 과거 캐시가 있으면 '이전 저장 데이터'로 표시
               └─ 없으면 오류 표시 (실데이터로 가상 자료 대체 금지)
    ↓
통계 분석 및 화면 표시
```

**현재 구현:** `market_data.fetch_historical()`은 국내 6자리 코드에 대해 `NAVER:<종목코드>`를 먼저, 실패하면 `KRX:<종목코드>`를 차례로 시도한다. 날짜/종가/거래량 기초 검증 및 CSV·메타 JSON 저장, 이전 캐시 강등 표시가 동작한다. 단, **수정주가 공급자 간 완전한 동일성 검사·거래정지 판정·실제 API 연동 시험은 아직 완성되지 않았다.**

### 5.4 저장·캐시 정책

현재 구현은 `data_cache/<종목코드>.csv` 및 `data_cache/<종목코드>.meta.json`을 저장하고 수집 실패 시 이전 파일을 `cached` 상태로 사용한다. `retrieved_at`, `source`, 요청 기간, 최종 거래일을 함께 기록한다. 추가로 아래 고도화를 계획한다.

- 가격 데이터와 **출처 메타데이터**를 따로 관리한다.
- 데이터 출처·요청 기간·실제 저장 기간·수집 완료 시각을 기록한다.
- 재수집 시 동일 거래일 중복, 비정상 가격, 누락 날짜를 검사한다.
- 캐시가 최신이라고 추측하지 않고 **거래소 기준 최종 거래일과 비교**한다.
- API 실패 시 오류 이유를 로그에 남기되 인증키·민감한 헤더는 기록하지 않는다.
- CSV 파일만 있어도 오프라인 분석할 수 있도록 원시 데이터와 파생 지표를 구분한다.

예시 메타데이터 형식(**현재 구현과 같은 필드의 설명용 예시**):

```json
{
  "stock_code": "005930",
  "source": "provider_name",
  "requested_from": "2024-01-01",
  "requested_to": "2026-11-11",
  "last_trade_date": "YYYY-MM-DD",
  "retrieved_at": "YYYY-MM-DDTHH:MM:SS+09:00",
  "adjusted_price": "unknown",
  "status": "cached"
}
```

위 내용은 **데이터 구조 예시**이지, 실제 수집된 시장 값이나 실제 캐시 파일이 아니다.

### 5.5 실제 가격·시세 상태 표현

- **실시간 체결가:** 계약·연결된 실시간 API로 확보했을 때만 표기한다.
- **지연 시세:** 제공처가 지연 시간을 알려준 경우 그 값을 표시한다.
- **과거 일별 종가:** 해당 거래일이 완료된 가격 데이터다.
- **이전 저장 데이터:** 새로 수집하지 못해 기존 CSV를 사용하는 경우다.
- **가상 데이터:** 교육 목적의 컴퓨터 생성 데이터다.

시세 기준 시각을 모르면 **`갱신 시각 확인 불가`**라고 적는다. 마지막 거래일이 오래되었다고 해서 휴일·거래정지 여부를 확인하지 않고 무조건 수집 실패라고 판단하지 않는다.

### 5.6 데이터 품질 및 기업행동

다음 경우를 데이터 품질 경고 또는 분석 제외 조건으로 관리한다.

- 중복 날짜, 잘못된 형식, 결측값, 음수·0 종가, 음수 거래량
- 극단적 비정상 값, 분할·병합·권리락·배당으로 인한 가격 불연속
- 거래정지·상장폐지·이전상장 등에 따른 데이터 공백
- 서로 다른 제공처의 수정주가/원시주가 혼용
- 기업별 거래일 불일치, 시차, 상장일 차이

데이터를 자동 수정할 때는 삭제·보정 내역이 추적 가능해야 하며, 기업행동으로 인한 움직임을 ‘이상 사건의 확정 원인’으로 판정하지 않는다.

## 6. 통계 분석과 기술적 지표

### 6.1 현재 구현된 통계 계산

이 절의 기본값은 `stock_core.py` 기준이다. 비교 기간 `N`은 UI에서 10~60거래일로 조절하며 초기값은 20이다.

| 지표 | 정의 | 구현 상태 |
|---|---|---|
| 일일 수익률(%) | `(Close[t] / Close[t-1] - 1) × 100` | 구현됨 |
| N일 단순이동평균 | 최근 N일 `Close`의 산술평균 | 구현됨 |
| N일 변동성 | 최근 N개 일일 수익률의 **표본표준편차**, 비연율화 | 구현됨 |
| 가격 급변 Z점수 | `abs(Return[t] - mean(Return[t-N:t-1])) / std(Return[t-N:t-1])` | 구현됨 |
| 거래량 배율 | `Volume[t] / mean(Volume[t-N:t-1])` | 구현됨 |
| MDD(%) | 선택 기간 중 `(Close[t] / 누적최고종가[t] - 1) × 100`의 최솟값 | 구현됨 |
| 비교 종목의 지수화 | 시작일 종가를 100으로 환산하여 변화 비교 | 구현됨 |

**중요한 차이:** 변동성 차트는 *당일 포함* 최근 N개 수익률을 사용하지만, 당일 급변 여부를 판정하는 **평균·표준편차·평균 거래량은 `shift(1)`로 당일을 제외**한다. 따라서 ‘오늘을 평가하는 과거 기준에 오늘이 포함되지 않는다’는 설명이 정확하다.

표본표준편차가 0이면 통상적인 Z점수는 정의되지 않는다. 기존 코드는 정상 분포를 임의 가정하지 않고 **이전 수익률과 달라졌는지**를 별도 규칙으로 판정한다. 평균 거래량이 0일 때도 같은 방식으로 0 나눗셈을 피한다.

### 6.2 거래량·매매 활동 분석(주요 표시 기능 구현, 일부 확장 예정)

- 거래량 막대그래프 및 N일 평균 거래량
- 전일 대비 거래량 변화율
- 평균 거래량 대비 급증 배율
- 실제 거래대금(제공처가 제공하는 경우)
- 가격 상승·하락과 거래량 증가·감소의 동시 발생 패턴

**거래량 급증 = 매수세 우위**라고 자동 판단하지 않는다. 거래량만으로 개별 매수·매도 주체나 향후 방향을 확정할 수 없기 때문이다.

### 6.3 기술적 지표 확장(현재 계산 코드 구현, 후속 개선 예정)

| 지표 | 활용 목적 | 구현 시 주의 |
|---|---|---|
| SMA 5/10/20/60/120 | **구현됨** · 단기·중기 추세 확인 | 창 길이보다 짧은 구간은 결측 처리 |
| EMA 12/26 | **구현됨** · 최근 가격에 가중한 추세 | ewm(adjust=False), 최소 관측일 지정 |
| RSI(14) | **구현됨** · 최근 상승·하락 폭의 상대적 강도 | alpha=1/14 지수평활 기반 |
| MACD(12,26,9) | **구현됨** · 두 EMA 차이와 신호선 | 12/26 EMA 및 9 신호 EMA |
| 볼린저 밴드(20, 2) | **구현됨** · 최근 평균과 변동폭 범위 | 종가 표본표준편차 |
| ATR(14) | **구현됨(OHLC 자료가 있을 때)** · 가격 변동폭 | 고가·저가가 없으면 NaN |
| 52주 최고·최저 | 과거 약 1년의 가격 범위 | 실제 거래일·상장기간 확인 |
| 시장 대비 상대수익률 | 개별 종목과 KOSPI·KOSDAQ 비교 | 동일한 관측 시점·가격 기준 사용 |

기술적 지표는 **과거 패턴을 정리하는 입력 변수**다. 지표 한 개가 미래 수익을 보장하거나 매매 신호를 확정하는 것은 아니다.

### 6.4 급변 탐지와 미래 급변 예측의 차이

- **급변 탐지:** `t`일 거래가 끝난 뒤, 이미 관측된 `t`일 수익률이 과거 `N`일의 범위에서 이례적인지 평가한다.
- **급변 예측:** `t`일에 확인 가능한 데이터만으로 `t+1`일 또는 이후에 이례적인 움직임이 *발생할 확률*을 추정한다.

두 기능의 입력, 정답(label), 평가 기준은 다르며, Z점수를 미래 상승 확률처럼 표시해서는 안 된다.

## 7. 금융 뉴스·기업 공시 분석

> **개정판 MVP 구현:** NAVER 뉴스 검색(키 필요), OpenDART 공시 조회(키 필요), CSV 뉴스 업로드, 키워드 기반 기사 주제·감성 분류, 최신 기사 목록 및 시점 정보 표시. 자동 본문 수집·학습형 금융 NLP·정교한 중복 사건 병합은 아직 개발 대상이다. 실제 API 통신은 모의 테스트 외 별도 검증이 필요하다.

### 7.1 도입 이유

주가는 기업 실적, 정책, 산업환경, 시장 심리, 예상치와 실제 결과의 차이 등 다양한 요소에 영향을 받는다. 뉴스는 이러한 배경을 파악하는 데 도움이 되지만 **긍정적인 기사가 곧 주가 상승의 증거는 아니다.** 뉴스 분석은 가격 데이터와 별도 특성으로 다루고 기여도를 검증한다.

### 7.2 수집 범위와 데이터 규칙

수집 대상은 종목 관련 보도, 산업 뉴스, 거시경제 기사 및 **공식 기업 공시**다. 뉴스 API가 제공하는 범위 내에서 **제목·요약·URL·언론사·공개 시각**을 우선 확보하며, 본문 저장·AI 입력·재배포는 각 제공처의 허가 조건을 별도로 확인한다.

| 필드 | 설명 |
|---|---|
| `article_id` | 중복 제거용 내부 식별자 |
| `stock_code` | 연관 종목코드(복수 가능) |
| `title`, `description` | 허용된 제목·요약 |
| `publisher`, `source_url` | 원출처 및 사용자 확인 링크 |
| `published_at` | 원문에 표시된 공개 시각(타임존 명시) |
| `first_seen_at`, `collected_at` | 시스템이 최초 확인·수집한 시각 |
| `source_type` | 뉴스/공시/기타 |
| `topic`, `relevance_score` | 이슈 유형 및 종목 관련성 |
| `sentiment_label`, `sentiment_score` | 감성 분류 결과(모델 버전 포함) |
| `license_status` | 활용·저장 허용 범위 |

**원칙:** 기사가 검색된 시점과 실제 공개된 시점은 다를 수 있다. 정정 기사·다중 보도·잘못 매칭된 종목은 별도 처리한다. DART의 `corp_code`와 증권사의 6자리 `stock_code`는 구분해서 매핑한다.

### 7.3 뉴스 분석 처리 단계

```text
뉴스/공시 공식 API
       ↓
종목·산업 관련성 판별
       ↓
중복 기사·동일 사건 묶기
       ↓
제목/요약 정제 및 주제 분류
       ↓
긍정·중립·부정 감성 분석
       ↓
일별 뉴스 변수로 집계
       ↓
주가/거래량 지표와 시점 정렬
       ↓
기사 목록·출처·AI 설명 표시
```

**분류 예:** 실적, 투자/계약, 제품 출시, 업황, 정책, 금리/환율, 공급망, 소송·리스크. ‘적자 축소’처럼 겉으로는 부정적인 단어가 있어도 실질적으로 개선을 의미하는 문맥을 고려한다.

### 7.4 감성 점수와 뉴스 변수

감성 라벨은 `긍정 / 중립 / 부정`으로 나눈다. 시연용 감성 점수는 예를 들어 -1~+1 범위로 표준화할 수 있으나, 이 점수는 **주가 수익률이나 상승 확률이 아니다**.

예측 피처 예시:

- 예측 시각까지 확인 가능한 **최근 1·3·7일의 관련 기사 수**
- 종목 관련성으로 가중한 **평균 감성 점수**
- 부정·긍정 사건의 비율, 주제별 기사 수
- 새 공시 발생 여부와 공시 유형
- 동일 사건을 여러 매체가 보도한 중복 정도
- 시가총액 대비/업종 대비 뉴스 변화(추가 자료 확보 시)

### 7.5 시점 누출 방지 — 뉴스에서 가장 중요

`2025년 3월 4일 장 마감 기준`으로 예측한다면 **그 시점에 실제로 알려져 있었던 기사만** 사용해야 한다. 이후 공개된 기사나 나중에 갱신된 요약·검색 결과를 과거에 이용 가능했던 것처럼 포함해서는 안 된다.

장 마감 시점을 예측 기준으로 정했다면 `published_at <= cutoff`는 최소 조건이다. **진짜 과거 시점 재현**에는 당시 수집·기록된 기사 아카이브 또는 신뢰할 수 있는 당시 가용성 기록도 필요하다. 오늘 검색한 과거 기사 목록만으로 과거의 뉴스 접근 가능성을 완벽하게 복원할 수 없으므로, 그런 검증은 **제한적·탐색적 백테스트**로 표시한다.

### 7.6 생성형 AI 요약 원칙

생성형 AI를 추가하더라도 설명은 **수집된 원문 링크·허용된 요약·계산 지표에 근거**해야 한다. 존재하지 않는 기사, 수치, 인과관계를 지어내지 않으며, 출처가 확인되지 않으면 해당 부분을 출력하지 않는다. 텍스트 모델의 설명력과 예측 모델의 통계적 정확도는 별도로 평가한다.

## 8. AI 예측 설계: 무엇을, 언제, 어떻게 예측하는가

> **개정판 구현:** 다음 거래일 `Close[t+1] > Close[t]` 이진 분류를 로지스틱 회귀 모델로 구현하고 60/20/20 시간순 분리, 1행 경계, 기준 모델과 비교한다. 5거래일 수익률·미래 급변 확률·딥러닝은 아래의 확장 규격일 뿐 현재 미구현이다.

### 8.1 예측 문제를 먼저 고정한다

**주 예측 문제 — 장 마감 기준 다음 거래일 상승 여부**

- **입력 확정 시점:** 거래일 `t`의 정규장 마감 후, 필요한 가격·기사 데이터 수집이 완료된 시각
- **목표 시점:** 다음 거래일 `t+1` 종가
- **정답(label):** `y[t] = 1` if `Close[t+1] > Close[t]`, else `0` (보합은 비상승으로 포함)
- **출력:** `P(y[t]=1 | t 시점까지의 데이터)` 및 보완 지표
- **경계:** 이 확률은 충분한 검증·보정 전에는 **검증된 실제 확률**이라고 부르지 않음

예측 시각을 ‘종가 확정 전’으로 바꾸는 경우에는 `Close[t]`, 당일 최종 거래량처럼 아직 확정되지 않은 값을 입력할 수 없으므로 **별도 모델**로 다룬다.

**추가 예측 문제(후속 개발)**

1. **5거래일 후 방향**: `Close[t+5] > Close[t]` 여부
2. **5거래일 누적 수익률**: `(Close[t+5]/Close[t]-1)×100` 회귀 예측
3. **향후 N거래일 변동성**: N일간 미래 수익률의 표본표준편차 회귀 예측
4. **미래 급변 발생 가능성**: 향후 기간에 미리 정의한 급변 조건이 성립할 확률

여러 개를 한 번에 섞지 않고 **모델별 예측 대상·기간·정답 정의를 고정**한다.

### 8.2 입력 피처(feature) 설계

| 유형 | 예시 변수 | 입력 가능 조건 |
|---|---|---|
| 수익률 | 1·5·20거래일 누적 수익률 | 기준 시각까지 종가 확정 |
| 추세 | SMA·EMA, 이격도, 기울기 | 과거 값만으로 계산 |
| 모멘텀 | RSI, MACD, 최근 연속 상승일 | 결측·초기 구간 처리 |
| 위험 | 과거 변동성, 과거 최대 낙폭 | 당일 완료 시점까지 |
| 거래 활동 | 거래량 배율, 거래량 변화율 | 해당 거래일 수치 확정 |
| 시장 | KOSPI/KOSDAQ 수익률, 업종 상대수익률 | 동일 기준시각 일치 |
| 뉴스 | 감성 점수, 기사 수, 이슈 유형 | 공개·가용 시각이 기준 이전 |
| 공시 | 공시 발생 여부, 발표 유형 | 공식 공개시각 확인 |
| 거시 | 환율·금리 변화 | 해당 시점 실제 발표값만 사용 |

결측값, 이상치, 스케일링, 인코딩 방식은 **학습 구간에서만 적합(fit)**하고 검증·테스트에 같은 변환을 적용한다. 타깃 날짜의 정보를 피처 생성에 섞지 않는다.

### 8.3 단계별 모델

| 모델 | 목적 | 평가 포인트 |
|---|---|---|
| 기준 모델(Baseline) | 학습 없이 과거 빈도 또는 단순 추세 사용 | 복잡한 모델의 비교 기준 |
| Logistic Regression | **현재 구현** · 다음 거래일 방향의 기본 확률 모델 | 기본 `predict_proba`는 미보정 추정치, Brier 검증 동반 |
| Random Forest | **미구현** · 비선형 패턴의 추가 학습 | 과적합·피처 중요도·시간 검증 |
| Gradient Boosting(선택) | 성능 개선 가능성 탐색 | 과적합 통제·재현성 |
| 가격+뉴스 결합 모델 | **조건부 구현** · `first_seen_at` 충분한 경우만 | **가격만 사용한 모델과 동일 테스트 구간 비교** |

딥러닝(LSTM·Transformer)을 반드시 도입할 필요는 없다. **검증된 단순 모델**이 검증되지 않은 복잡한 모델보다 프로젝트 목표에 더 적합할 수 있다.

### 8.4 출력 형식

최종 웹앱은 다음을 명확히 표시해야 한다.

- 분석 종목 및 종목코드
- **예측 생성 시각(KST), 예측 기준 거래일, 목표 거래일**
- 해당 시점에 사용 가능한 데이터의 최종 시각
- 예측 모델·버전·학습 및 평가 기간
- 다음 거래일 상승 **추정 확률**(검증 결과 동반)
- 예측 불확실성·이상치·데이터 부족 경고
- 주요 입력 변수와 근거 기사/공시 링크
- 평가 데이터의 정확도, Brier Score, 표본 수, 기준 모델 대비 성능

**UI 형식 예시 — 임의 시연값, 실제 주가 분석 아님:**

```text
MARKET PULSE · AI ANALYSIS [DEMO / SYNTHETIC]
종목: 가상기업 A
모델: logistic-regression / demo-v1
예측 기준: 가상 거래일 t 장 마감
예측 대상: 가상 거래일 t+1 종가 상승 여부
상승 추정 확률: 0.58 (시연값)
비상승 추정 확률: 0.42 (시연값)
검증 상태: 데모 - 실제 시장 예측력 검증되지 않음
주요 입력: 최근 수익률, 거래량, 이동평균, 뉴스 점수(가상)
```

진짜 모델의 출력에는 **평가 결과와 기록된 예측 ID**가 연결되어야 하며, 임의로 만든 ‘상승 확률 80%’ 같은 숫자를 사실처럼 표시해서는 안 된다.

### 8.5 예측 실패 시 동작

- 필요한 가격·뉴스 데이터가 없거나 시점 검증에 실패하면 **예측 불가**로 표시한다.
- 검증 성능이 기준 모델보다 나쁘다면 결과에 그 사실을 표시하고 과도한 확신 표현을 금지한다.
- 모델 파일을 읽지 못하거나 버전이 불일치하면 이전 모델 수치를 새 예측처럼 보여주지 않는다.
- 모델 훈련 구간과 실제 사용자 종목의 특성이 현저히 다르면 분포 변화(shift) 경고를 제공한다.

## 9. 백테스트·성능 검증·모델 설명

**개정판에 실제 구현된 것:** `backtesting.py`에서 60/20/20 순서 분리, 평가 경계 직전 1개 행 제외, 마지막 시험 구간의 분류 지표/Brier/LogLoss, 학습 구간 기준 빈도 `DummyClassifier`, 선택형 3분할 Walk-forward를 계산한다. `model_explainer.py`는 로지스틱 회귀 피처의 표준화 계수 기여도를 계산한다. 예측값의 자동 영구 저장 및 모델 레지스트리는 후속 개선 대상이다.

### 9.1 시간순 데이터 분리

주식시장 데이터에는 시간 순서가 있으므로 미래 관측값을 학습에 이용하지 않는다.

```text
과거 ───────────────────────────────────────▶ 미래
[모델 학습 기간] [모델 조정 기간] [최종 미사용 테스트 기간]
         └───────── 과거 → 미래의 한 방향 ───────┘
```

- `train`에서 모델 학습 및 전처리 모수 결정
- `validation`에서 하이퍼파라미터·기준값·확률 보정 결정
- `test`는 최종 선택이 끝난 뒤 **한 번 평가하는 미사용 구간**으로 유지
- 추가로 **walk-forward(전진 이동) 검증**을 사용해 여러 시기에서 평가
- `t+5` 같은 겹치는 미래 타깃을 사용하는 경우 학습·검증 경계에 필요한 간격을 둔다.
- 기업 다수를 섞어 학습할 경우에도 동일 날짜에서 미래 정보가 다른 종목을 통해 전달되지 않도록 시간 경계를 통일한다.

### 9.2 성능 평가 지표

| 대상 | 필수 지표 | 해석 시 주의 |
|---|---|---|
| 상승·비상승 분류 | Accuracy, Precision, Recall, F1 | 클래스 불균형 고려 |
| 확률 예측 | **Brier Score**, Log Loss, Reliability Diagram | 숫자가 확률처럼 보이는 것과 실제 보정 여부는 다름 |
| 수익률 회귀 | MAE, RMSE | 단순 0% 예측과 비교 |
| 예측구간 | 실제 포함률, 평균 구간 폭 | 범위가 넓다고 좋은 모델이 되는 것은 아님 |
| 급변 예측 | Precision/Recall, 오탐·미탐 건수 | 희소 사건의 정확도만 보면 오해 가능 |

예측 건수와 평가 기간도 함께 표시한다. 실험을 반복해 가장 높은 점수만 발표하지 않고, 기준 모델 대비 실제 개선 여부와 불확실성을 기록한다.

### 9.3 반드시 비교할 실험

- **실험 A:** 가격·거래량만 사용
- **실험 B:** A + 기술적 지표
- **실험 C:** B + 금융 뉴스 감성·기사 수
- **실험 D(선택):** C + 시장지수·공시·거시 변수

모든 실험은 **같은 타깃, 같은 시간 분할, 같은 평가 구간, 같은 평가 지표**로 비교한다. 특히 **C가 B보다 좋아지는지**가 뉴스 분석의 실질적 가치를 검증하는 핵심 질문이다.

### 9.4 설명 가능한 AI

예측 설명에는 적절한 기술을 선택한다.

- 로지스틱 회귀: 표준화된 입력 변수의 계수·방향 등 제시
- 트리 모델: 순열 중요도 등 *예측에 기여한 변수*를 검토
- 전체/개별 예측: 설명 결과가 원인 확정이 아님을 명시
- 뉴스 변수: 어느 기사·공시가 언제 포함되었는지 링크 제공

**주의:** 피처 중요도가 높다고 해서 해당 변수가 주가 상승의 **원인**이라고 증명된 것은 아니다.

### 9.5 재현성 관리

예측 및 평가마다 다음 메타데이터를 기록한다.

```text

```

같은 코드·데이터 스냅샷·설정·난수 시드를 사용하면 결과를 재현할 수 있어야 한다.

- **`stock_core.calculate_indicators(raw,window,z_limit,q_limit)`** → 현재까지의 수익률·과거 기준 급변 판정이 포함된 데이터프레임.
- **`technical_indicators.add_indicators(raw)`** → SMA·EMA·RSI·MACD·ATR 등의 파생 컬럼.
- **`news_collector.fetch_naver_news(query,code)`** → 기사 제목·요약·링크·게시시각·첫 확인 시각 메타데이터.
- **`disclosure_collector.fetch_disclosures(code,start,end)`** → OpenDART 공시 목록(키 필요).
- **`news_analyzer.analyze_articles(frame)`** → 키워드 규칙형 감성·주제·근거 단어.
- **`feature_engineering.prepare_feature_table(price,news)`** → t일 입력과 `TargetUp[t]`(t+1 결과).
- **`prediction_model.run_experiments(price,news)`** → 2~3가지 모델 비교표, 최신 추정 확률, 시험 구간 예측표.
- **`backtesting.walkforward_scores(table,features)`** → 시간순 반복 평가표.

**현재 파일 사이 데이터 형식은 Pandas DataFrame이며, 외부 사용자 계좌·주문 데이터나 실시간 호가를 사용하지 않는다.**

### 11.4 CSV 입력 명세(현재 지원)

**필수 열:** `Date`, `Close`, `Volume` 또는 `날짜`, `종가`, `거래량`. `Open/High/Low`는 선택 사항이다. UTF-8 BOM·CP949 파일을 지원하며, 현재 주가·거래량 열의 쉼표 숫자도 처리한다.

```csv
Date,Open,High,Low,Close,Volume
2025-01-02,100,103,99,102,1000
2025-01-03,102,104,101,103,1200
2025-01-06,103,103,98,99,1500
```

이 CSV는 **형식 예시용 가상값**이며, N일 급변 점수 분석을 수행하기에는 거래일이 부족하다. 유효한 평가일을 얻으려면 통상 **N+2거래일 이상**이 필요하고, 시작일 직전의 충분한 이력도 포함해야 한다.

NAVER 공급자를 시도하고 실패하면 KRX 공급자를 재시도한다. **두 제공처가 모두 실패했을 때만 과거 캐시가 있다면 `cached` 상태**로 불러온다. CSV가 없으면 오류가 발생하며, 성공했다고 꾸미지 않는다. 파일은 `data_cache/<종목코드>.csv` 및 `<종목코드>.meta.json` 형태로 생성된다. 실제 데이터가 미리 들어 있는 것은 아니다.

### 12.5 데이터 모드와 화면

**기본 모드 = `국내 주식 실데이터`**이다. 원격 데이터가 불가능한 환경에서는 사용자가 **`가상 데이터(오프라인)`**를 직접 선택한다. 가상 종목은 A~D이며 뉴스도 **352개 합성 기사 전체 중 선택 종목의 기록**을 사용한다. `CSV 직접 업로드` 모드에서는 `Date/Close/Volume` 또는 한글 동의어를 가진 CSV를 지원한다.

분석 기준: 시작일=실행 날짜 약 3년 전, 종료일=실행 날짜, N=20(10~60), Z=2.5(1.5~4.0), 거래량 급증 배율=1.5(1.2~3.0). 날짜 입력 값은 사용자가 바꿀 수 있다.

현재 **7개 탭**:

1. `📊 대시보드`: 종목별 평균 변동성과 가격 변화 및 선택형 KOSPI/KOSDAQ 과거 지수 요약
2. `📈 종목 상세`: 종가/변화율, OHLC 캔들 또는 종가선, 거래량, RSI, SMA, 변동성, 기술 지표 저장
3. `🚨 급변 탐지`: 기존 과거 급변 분류, 조회·다운로드
4. `📰 뉴스·공시`: NAVER 검색 메타, OpenDART 공시, CSV 업로드, 규칙형 감성·주제 표시
5. `🤖 AI 예측`: 가격-only/기술지표/조건부 뉴스 모델의 다음 거래일 확률·평가 비교
6. `🧪 백테스트`: 시험 기간 내역, 확률 보정 참고 그래프, 선택형 Walk-forward와 탐지 민감도
7. `⚙️ 데이터·설명`: 출처 메타데이터, 계산 수식, 주의사항 및 API 설정

### 12.6 뉴스 API 키 설정

사용자 PC의 환경변수 또는 프로젝트 밖의 안전한 설정에 다음 값을 저장한다.

```text
NAVER_CLIENT_ID=발급한_NAVER_클라이언트_ID
NAVER_CLIENT_SECRET=발급한_NAVER_클라이언트_시크릿
DART_API_KEY=발급한_전자공시_인증키
```

**실제 값은 코드·README·GitHub에 넣지 않는다.** `.env.example`은 이름만 설명하는 견본이고, `config.get_secret`은 현재 OS 환경변수 또는 Streamlit Secrets를 조회한다. `.env` 파일을 만들기만 해서는 자동 로드되지 않는다. Streamlit Secrets를 쓴다면 `.streamlit/secrets.toml`에 올바른 형식으로 저장하고 `.gitignore`를 유지한다.

기능별 요구 키: NAVER 검색은 앞의 두 키, OpenDART는 `DART_API_KEY`. API 키가 없어도 가상 데이터 및 사용자가 업로드한 뉴스 CSV로 연습할 수 있다.

### 12.7 뉴스 CSV 예시

```csv
title,description,published_at,first_seen_at,stock_code,source_url
가상기업 A 실적 개선,합성 교육용 기사,2026-01-02T13:00:00+09:00,2026-01-02T13:05:00+09:00,가상기업 A,
```

위 값은 **가상 시연**이다. `first_seen_at`은 과거 예측의 정직한 재현에 매우 중요하다. 값을 모른다면 빈칸을 유지해야 하며 오늘 검색한 기사를 옛날에 이미 관찰한 것처럼 기록하면 안 된다.

### 12.8 Colab 노트북

`MARKET_PULSE_Colab.ipynb`는 별도 실습 환경이다. Colab에서 ZIP을 업로드한 뒤 가상 데이터 기반 급변 분석, 가상 뉴스 감성, 다음 거래일 ML 예측 및 시험 결과를 순차 실행한다. **Streamlit UI는 이 노트북의 실행 화면이 아니며** 별도로 앱을 시작해야 한다.

### 12.9 가상 분석 결과 CSV 예시

`sample_outputs/`에는 새로 실행한 가상기업 A의 비교표·급변 탐지·세 모델 시험 점수·다음 거래일 추정 확률 결과를 저장했다. **각 CSV의 `데이터상태`가 `demo`**이며, 실제 투자 종목의 분석 결과가 아니다. 숫자는 실험 재현을 위한 예시일 뿐이다.

### 13.2 테스트가 실제로 확인한 내용

- 데이터 중복·음수·결측·유효 기간 처리, Z점수·거래량 이상 판정

- 두 제공처 모두 실패했을 때 이전 캐시가 최신 데이터로 표시되지 않는지
- 캐시가 없는 상태에서 실데이터를 임의 생성하지 않는지
- OHLCV 및 시장지수의 가격·거래량 기본 형식
- 종목 코드 검증과 종목 이름 목록의 자료형 변환
- 실제 기사가 아닌 합성 문장 기반 뉴스 정제·중복·키워드 분류
- 공개 시각과 `first_seen_at`이 다를 때의 정보 가용 시각 처리
- 장 마감 **이후** 기사와 최초 조회가 늦은 기사의 소급 사용 금지
- `t`일 피처 생성에서 `t+1` 가격 정보가 혼입되지 않는지
- 가격만/기술지표/뉴스 포함 세 모델의 같은 시험 기간 평가
- 분류 확률 0~1 범위, 1행 경계, Walk-forward 시계열 순서 확인
- OpenDART corp_code ZIP 파싱 및 공시 날짜의 보수적 시간 처리

- [x] 뉴스·공시의 **관측된 가용 시각**을 고려한 보수적 시간 정렬(역사적 완전성은 미검증)

## 16. 문제 해결 및 한계

### 16.1 설치 중 Python 오류

- `python`이 인식되지 않으면 Windows에서 `py -3 --version`으로 확인한다.
- 프로젝트 폴더에 `requirements.txt`가 있는지 확인한다.
- 회사·학교 PC라면 Python 설치 권한이나 방화벽이 제한될 수 있다.
- 패키지 충돌 시 별도 가상환경 `.venv`에서 설치하는 방식을 권장한다.

### 16.2 `localhost:8501` 접속 실패

- Streamlit 프로세스가 실제 실행 중인지 터미널 오류를 확인한다.
- 포트 8501이 다른 프로세스에 사용 중이면 터미널의 실제 표시 URL을 따른다.
- 프로그램이 실행되는 PC에서 `localhost`에 접속한다. 다른 PC·휴대폰은 배포 또는 네트워크 설정이 별도로 필요하다.

### 16.3 실제 종목 가격이 나오지 않음

- 왼쪽에서 **국내 주식 실데이터**를 선택했는지 확인한다.
- 인터넷, 종목코드, 기간, 금융 데이터 제공처 상태를 확인한다.
- 가격 수집이 실패하면 저장된 데이터가 있는지 확인하고 **이전 데이터임을 명시**한다.
- 가상 데이터를 실제 가격으로 표시하지 않는다.

### 16.4 급변 내역이 없거나 데이터가 부족함

- 비교기간 `N=20`이면 적어도 `N+2`개 거래일 수준의 이력이 필요하다.
- 분석 시작일 *이전* 자료가 있어야 시작일 직후의 급변 기준을 계산할 수 있다.
- Z 기준을 높이면 탐지 건수가 줄 수 있지만, 탐지 횟수만으로 정확도를 판단할 수 없다.

### 16.5 뉴스·예측 탭이 보이지만 결과가 없음

개정판에서는 7개 탭이 제공된다. 뉴스 API 키가 없으면 실제 기사 조회 버튼이 비활성화되고 CSV 업로드나 가상 데이터 사용이 가능하다. 예측 탭에서는 별도의 실행 버튼을 눌러야 모델 계산이 시작된다. 학습 행 부족, 클래스 하나뿐인 자료, 실제 최초 확인 시각 부족 때문에 뉴스 포함 모델이 제외될 수 있다. 이는 의도된 데이터 품질 통제다.

### 16.6 통계·예측의 본질적 한계

- 과거 시계열의 관계가 시장 환경 변화 후에도 유지된다고 보장할 수 없다.
- 주가 변동에는 뉴스 외에도 다양한 요인이 동시에 작용한다.
- 뉴스 감성은 기업에 유리·불리한 표현을 분류한 결과이지 수익률 예측값이 아니다.
- 급변 탐지는 통계적 이례성을 보여줄 뿐 사건의 경제적 원인을 확정하지 않는다.
- 상장폐지 종목을 제외한 일부 생존 종목만 학습하면 생존편향이 발생할 수 있다.
- 뉴스 데이터를 현재 검색해 과거를 재구성하면 당시 보이지 않던 정보가 섞일 수 있다.
- 낮은 표본 수, 불균형한 급변 사건, 과적합, 데이터 누출, 거래소 거래일 차이는 예측 결과를 왜곡할 수 있다.

## 17. 수행평가 시연과 탐구 보고서 구성

### 17.1 5~7분 내외 시연 시나리오(개정판 실제 기능 중심)

1. **문제 제시:** 가격·거래량·뉴스가 분산돼 있어 한 번에 이해하기 어려운 점 소개.
2. **데이터 입력:** 가상 데이터 모드 선택 또는 실제 CSV 업로드.
3. **통계 원리 설명:** 수익률, N일 표준편차, Z점수, 평균 거래량 대비 배율.
4. **급변 탐지:** 급등·급락·거래량만 급증하는 사례를 차트와 표로 비교.
5. **검증:** Z 기준 민감도 변화를 보여주고 탐지 횟수만으로 정확도를 주장하지 않음.
6. **가상 뉴스 분석:** 뉴스·공시 탭의 시연용 합성 기사와 키워드 감성을 확인한다.
7. **다음 거래일 AI:** AI 예측 탭에서 세 가지 모델을 학습시키고 오프라인 시험 지표를 비교한다.
8. **정직한 해석:** 뉴스 추가 모델이 반드시 좋아지지 않는다는 점과 Brier/기준 모델을 설명한다.
9. **향후 확장:** 실데이터 뉴스의 장기 가용 시각 기록, 더 풍부한 기사 분류와 실제 시장 검증이 필요함을 밝힌다.

### 17.2 수행평가 보고서 권장 목차

1. **개발 동기:** 일반 주식 사이트에서 수치를 보기만 할 때의 한계
2. **문제 정의:** 주가 급변 탐지와 미래 예측은 어떻게 다른가?
3. **데이터 출처:** 실데이터·가상 데이터, 출처 및 신뢰성
4. **알고리즘:** 수익률·변동성·Z점수·거래량 배율
5. **구현 과정:** Python 라이브러리, 자료구조, 예외 처리, UI
6. **실험 설계:** 탐지 기준 변화 / 뉴스 포함 여부 / 시간순 검증
7. **결과:** 실제 테스트 수치·차트·오류 사례
8. **한계와 개선:** API 제약, 데이터 누출, 과적합, 예측 신뢰성
9. **배운 점:** 데이터 중심 문제 해결, 알고리즘 구현, 검증 습관

### 17.3 이 프로젝트의 탐구 질문

- 기준 거래일 수를 10·20·40으로 바꾸면 **가격 급변 탐지 결과**가 어떻게 달라지는가?
- 같은 날의 **가격 변동 폭과 거래량 급증은 어느 정도 함께 나타나는가?**
- 뉴스 감성 변수를 추가했을 때 **보이지 않은 미래 기간**에서 방향 예측 성능이 실제로 개선되는가?
- 높은 분류 정확도를 가진 모델의 **상승 추정 확률도 신뢰할 수 있는가?**
- 시장 변동성이 높아진 기간에는 과거에 학습한 모델의 오류가 커지는가?

이 질문들은 모델을 만들었다는 사실보다 **분석 가능한 결과를 검증하는 역량**을 보여준다.
